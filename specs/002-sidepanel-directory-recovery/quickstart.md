# 验收指南

## 准备

使用 Node.js 24 和支持解包扩展的 Windows 桌面 Chrome。准备空测试目录、可复制的旧 `URLPut-data-v1` 样本、备份和恢复空目标。旧样本含来源行、回执、结果和未完成检查点。业务 API 和数据库保持关闭。

```sh
npm ci
npm run check
npm test
npm run package:chrome
```

从 `chrome://extensions` 加载 `apps/extension/.output/chrome-mv3`，固定扩展并点击工具栏按钮。对照 `75ea576` 的 [原型](../../docs/design/workbench-prototype.html) 和 `0482741` 的基线扩展。记录两个模式的区块、默认展开态、字段、启动条件及往返焦点，保存基线撤权截图。

## 路径及证据

| 规格 | 操作与预期 |
| --- | --- |
| SC-001 | 320 px 和 392 px 各检查六项导航、设置、全页入口、键盘和长 URL。截图记录加载、空、错误、禁用和有数据状态。 |
| SC-002 | 两个宽度各编辑可识别草稿，原生撤权并切回，先取消或拒绝，再成功授权。比对原区块、内容、预览和焦点。 |
| SC-003 | 初始化空目录、绑定旧目录、移动后重新绑定、备份到新目录后恢复。对照数据 ID、原始行、回执及检查点。保存一条新记录核对写入位置、原目录与备份。切到另一个工作空间时验证无效选择提示。 |
| SC-004 | 使用受控队列和写入故障注入复现中途撤权及运行时换绑。恢复后核对重复条数、请求记录、磁盘检查点和手工续跑。保持业务 API 和数据库关闭，记录本机目录流程的业务 API 请求数为 0。随后由开发方启动本地业务 API，用测试数据验证旧版服务工作空间可访问、历史可迁移且重复迁移不产生重复记录，单独保留请求与迁移证据。用户也可独立复验。 |

Linux 模拟路径可执行 `URLPUT_WEB_SMOKE=1 CHROMIUM_PATH=/usr/bin/chromium npm run test:extension`。也可用 `URLPUT_EXTENSION_DIR` 指向解包目录。模拟权限和故障注入按受控证据记录。归档每个场景的构建提交、Chrome 版本、入口、实测宽度、截图及对应目录或请求日志，并标记通过、未验证或受阻。

## 本轮验收记录

- 构建基线为 `0482741`，实现来自本地 `002-sidepanel-directory-recovery` 工作树。Node.js 24.22.3 上类型检查、20 项测试及打包通过。内测包位于仓库内 `apps/extension/.output/URLPut-WXT-0.1.0-chrome.zip`。
- Chromium 156.0.8078.79 在 320 px 和 392 px 复核原型 `75ea576` 的六项导航、两个模式的五或八个区块。推广站点默认展开，外链清单、筛选和执行模式的认证区默认收起。清空外链后启动禁用，前往清单再返回时焦点回到推广站点区块。
- 相同浏览器与宽度直接打开基线和候选版的 `sidepanel.html`，用持久文件系统夹具模拟撤权。基线草稿消失，候选版保留输入和预览。截图保存在工作区 `work/evidence-002`。
- 使用临时 PGlite 数据目录实际运行 `apps/api/src/main.ts --local`，`/health` 与 `/api/workspaces` 均返回 200。浏览器迁移回归另启 Fastify 与 PGlite 测试实例。
- 最终 ZIP 解包后通过完整 Chromium 受控回归。两种宽度均通过模拟撤权、拒绝、重授、回焦和长 URL 检查。换绑执行锁、批次文件已落盘但索引写入失败后的幂等重试、移动目录、备份恢复和队列续跑通过。关闭后端阶段业务 API 请求为 0。启动本地测试 API 后迁移同一站点两次，目标目录仍只有两个源批次，抽查候选来源行通过。
- 受管 Chromium 实际加载扩展尝试等待 Service Worker 15 秒超时。目标 Windows Chrome 工具栏入口和原生目录权限仍待验收。
