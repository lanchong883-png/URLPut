# 实施计划 · 03–10 本机多站批次

**日期** 2026-11-24
**工作分支** `002-sidepanel-directory-recovery`，承接现有 01–02 工作树
**规格** [spec.md](spec.md)
**状态** 已确认，实施中

## 技术背景

Node.js 24、TypeScript、React、WXT、Chrome MV3。目录授权句柄沿用 IndexedDB，业务记录仍写入用户目录的 `URLPut-data-v1`。已有本机单站批次、分段结果、串行锁、回执、台账、CSV、旧服务迁移和模型连通性测试可复用。现有队列由页面驱动，关闭侧栏后的生命周期和后台访问目录是首要验证点。Windows Chrome 的 01–02 原生权限仍待实机验证。

## 实施顺序

1. **03–05。** 先验证真实扩展从侧栏发起授权、后台可访问原句柄与关闭侧栏后继续的路径。确定可兼容的记录后，接通清单、筛选、五区块和不可变快照。以稳定启动 ID 提交快照与待启动状态，索引与队列可幂等补齐。小样本和 100,000 组合样本都通过后，验证任务详情、结果及导出。后台运行能力和共享请求槽随首个可启动多站批次交付。
2. **06–08。** 在同一执行与检查点机制上增加任务索引、分页、统计、暂停/中断/停止及继续。清单检查、分析和回访统一经过串行调度。已保存结果作为续跑起点，暂时失败按规格留证。为两张结果表与历史 CSV 分别核对归属、行 ID 和列顺序。
3. **09–10。** 增加模板版本、执行配置和草稿适配，先验收模型连通性与有证据的草稿生成。用测试样本实现人工批准、平台识别、尝试占位、额度和回执链。平台识别证据不足时转人工核对。先用受控站和测试时钟，获得站点授权后再做真实手动投稿验收。

## 项目结构与复用

- `apps/extension/entrypoints/` 承载侧栏和 Chrome 后台生命周期。
- `apps/extension/components/` 复用工作台、清单、分析、核验与投稿组件，沿用 01–02 的设置与恢复交互。
- `apps/extension/lib/` 复用目录读写、队列锁、现有结果、报告和模型设置。多站记录使用可区分的附加文件，适配旧批次读回；保留旧服务与迁移测试。
- `scripts/extension-smoke.mjs` 扩展受控浏览器验收。另记录真实侧栏日志和请求证据。

## 章程与风险

目标、作用域、兼容与验收已写入规格。先复用现有存储、样式和队列接口。只有 Chrome 实测需要时才引入扩展已有机制所需的额外入口。附加记录按版本识别，旧目录无需批量重写。发布前用旧目录和备份副本验收恢复。业务服务关闭和开启均由开发方测试并单独留证。外部投稿始终逐条批准、用户手动提交，接收回执与公开证据独立。设计复核暂无章程例外。真实 Chrome、授权站点和模型凭证的可用性是验收依赖，相应结论按实际证据记录。
