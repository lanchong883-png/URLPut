# URLPut 侧栏交互与视觉改造计划

核对基线为 `3a54c17`，实现提交为 `096bc69`，视觉原型为 `75ea576`。
本清单补充[本机版实施计划](implementation-plan.md)，以
[可点击原型](../design/workbench-prototype.html)、
[交互说明](../design/workbench-interaction.md)、
[产品需求](../requirements/product-requirements.md)及
[本机版验收记录](../requirements/local-acceptance.md)为依据。

Ego Lite 已确认工具栏能打开侧栏，直接打开扩展页面时复现了单站表单默认显示、
额外进入多站建批和空选时启动禁用。其余项目依据设计稿和源码比对，
每项的修复效果须在实际右侧面板验证。排期为依赖顺序。

## P0 · 统一建批入口及权限恢复

- **主入口。** 目前「新建批次」默认进单站导入，另点「多站建批」才出现五区块，
  原来的「保存并开始分析」可绕过确认。点击导航直接进入统一建批页。
  单站和多站共享流程，导入从对应区块跳转到清单。保留旧批次可读及全页备用入口。
- **草稿和权限。** 目录失权时保留当前区块、输入、选择和焦点定位。未绑定提示去设置，
  失权优先就地重授。明确区分加载中、用户拒绝、目录不可读、可重试和恢复成功。
  设置里的换绑、初始化、备份和恢复展示作用目录及操作结果。换绑后重新校验引用。
- **验收。** 从工具栏打开，分别用空目录及带历史的测试目录走单站、多站、清单往返。
  在填写中撤权，先取消再重授。验证草稿、焦点、历史和检查点完整，且启动只创建一批。

## P1 · 建批与清单

- **区块层级。** 当前是表单组堆叠，缺少与原稿一致的编号徽记和可折叠摘要。
  推广站点初始展开，外链清单及筛选初始折叠。编号统一，展开前能看到选择摘要。
  仅分析五区块，切换后八区块，来回切换恢复已填执行配置。
- **站点选择。** 当前列表主要显示站名与勾选。补站点网址、已选总数，每站显示
  总外链、已接收、待接收；提供搜索、待接收筛选、全选匹配及清空。
- **外链选择。** 当前候选主要展示 URL 和 DR。用紧凑列表显示域名、类型、完整
  URL、样本属性和评分，详情可查来源与日期。选用清单后默认选中活跃外链。
  筛选只改可见列表，「只选筛选结果」覆盖所有匹配项。收起筛选仍显示已应用条件，
  320 px 下允许折行。站点和外链每次追加 5 条，卡片内滚动自动加载。
- **确认与启动。** 补执行模式、内容策略及模板摘要；同时展示站点数、每站候选、
  合计、已接收和待接收。用清楚的就地反馈说明空选、上限无效、权限和启动失败。
  启动成功直接进入该批次详情。重试复用原批次，保持快照与去重保护。
- **清单维护。** 推广站点与外链清单切换放在页首。整理导入、检查结果、问题行下载、
  活跃列表、编辑与导出的操作层级。按原稿呈现新增、已有、重复和问题行，
  可从建批带回新增站点或所选清单。区分空清单、筛选无匹配和暂无检查结果。
- **验收。** 用两个站点、两份清单及超过五条的匹配数据测试滚动、换清单、空匹配、
  DR 0 与未知、补录返回。选两站并设每站上限三条，确认显示六个组合；
  修改源清单后旧批次仍按快照展示。另验证 100,000 组合计数与分段读取。

## P2 · 任务、详情、待确认和结果

- **任务入口。** 当前分别显示多站历史、旧批次操作与跨批待确认。整理为统一任务
  列表和待确认入口。保留名称、编号、状态筛选及分页，标题和行状态采用一致术语。
  点击进行中批次看进度，已完成批次直接看结果，返回保留筛选和原焦点。
- **进度及控制。** 将现有调度动作按状态呈现。主按钮只突出当前可用动作，
  中断和停止说明后果并确认。展示进度条、百分比、已处理与总数及当前检查点，
  支持整批和单站切换。待人工、限流、暂停、停止、完成用文字与颜色同时表达。
- **待确认与投稿。** 卡片展示推广站点、目标、原因、草稿和下一步。
  逐条批准和跳过的动作含义明确；已开始但回执未知时提供原记录核对入口。
  允许批量复核可安全核对的事项，逐条发表审批保留独立操作。
- **结果与导出。** 让「已完成网站分析」「已核验外链台账」从侧栏可明确找到。
  待审核留在来源任务，公开有效、明确失效与暂时访问失败按证据表达。
  侧栏用窄屏摘要加可展开明细，宽表留给备用工作台或导出。显示导出范围及结果。
- **验收。** 用执行中、待下一轮、待人工、已完成和历史批次检查入口和返回。
  对照全批及单站计数，验证暂停、中断、停止、重启恢复和同配置双窗口串行。
  逐条核对过滤后的 CSV、来源行、回执和证据。真实投稿使用获授权测试站。

## P3 · 执行配置和通用视觉

- **模板、认证及模型。** 认证导航目前禁用。按本机能力提供明确入口和状态，
  展示用户可用的人工登录、验证和逐条批准路径。模板管理与建批选择共用默认项，
  提供选中、已保存和不可用反馈；从模板管理返回保留原坐标与焦点。
  纯 AI 隐藏模板，模板或混合策略缺模板时说明原因。模型连接和草稿生成分别
  显示成功与错误，失败进入待确认。提交频率提示滚动额度和下次可运行时间。
- **侧栏视觉。** 保留原稿浅灰紫底、白卡片、靛紫主动作和固定六项导航。
  对齐编号、标题、说明、计数和操作按钮。删除重复标题，统一圆角、边框、
  字重、行高、留白和状态色。设置和备用工作台保持次级视觉层级。
  清单和任务使用一致的卡片与行内操作，避免导入区或宽表主导侧栏首屏。
- **响应式及键盘。** 320 px 和 392 px 检查导航、标题、字段、按钮、长网址、
  大计数、错误提示、滚动及页末启动按钮。保持主体无横向滚动，
  控件不截断，固定顶栏不遮焦点。用键盘完成建批并验证展开、回焦和状态通知。
- **验收。** 同宽对照原型和改造版截图，覆盖初始、有效选择、禁用、加载、空态、
  失败和有结果状态。用测试时钟验证额度，与授权目标站的人工作业路径分开记录。

## 执行与交付

先做 P0，再交付 P1，然后整理 P2，最后完成 P3 的执行配置。
卡片规范和窄屏布局随各阶段同步验收。复用已实现的目录、清单、队列、
回执和核验能力。按项目章程先确认跨模块 Specify 和 Plan，再进入实现。

从工具栏打开真实侧栏，分别记录入口、构建提交、浏览器版本和实测宽度。
使用原生目录及主机权限；记录截图、请求及适用的导出证据。
