# URLPut 实施时间计划

## 本机首版执行顺序

以[本机存储与结果报告](../architecture/local-first-results.md)为当前交付依据。先接入可配置数据目录并迁移既有导入与批次历史，完成停掉本地 API 和数据库后的浏览器回归，再交付已完成网站分析，最后交付已核验外链台账。每一步分别验证重启恢复和站点隔离。已有日期为旧方案估算，待迁移验证后重排。

## 原分阶段计划


本计划以 2026 年 11 月 21 日定稿的侧栏原型（提交 `75ea576`）为范围基线，目标是在授权测试站点完成 Chrome 扩展首版验收。排期按 11 月 23 日启动、两名工程师分别负责扩展和后端、测试人员参与阶段验收估算。预留 12 月 21 日至次年 1 月 3 日作为假期及联调缓冲。日期为预计交付窗口。

已有 WXT 和 Fastify 工程、CSV 与粘贴解析、模型连接测试及外链知识库 API。六个标签页的完整操作流程目前通过模拟数据演示。下表从正式扩展接入开始计时。

### 提前试用的三个交付点

扩展和后端按同一条用户流程并行开发，先用一种输入和一个授权测试站验收，再扩展覆盖范围。以下为可安装的内测包目标日期。每次交付在上一版上增加能力。

| 目标日期 | 用户可以试什么 | 出包条件 |
| --- | --- | --- |
| 11/27（第 1 周） | 安装扩展，在测试工作空间选推广站点，导入外链 CSV 并下载逐行台账。 | 复用现有 CSV 和 API，在干净的 Chrome 配置中完成一次真实导入，刷新后能查到正确站点的记录。 |
| 12/04（第 2 周） | 选择一批外链，对一个受控目录站运行只读分析，查看进度和导出结果。 | 扩展读取真实页面，记录入口、必填项及不可用原因。两个推广站点各选两条外链，单站导出两条。 |
| 12/18（第 4 周） | 在一个免登录的授权目录站，用预设模板完成一次经用户确认的投稿并查看回执。 | 同站点并发认领、提交前占位、额度检查及单条批准均通过测试。点击后断网只能进入只读核验。 |

第一周由扩展负责人打包并接入已有导入流程，后端负责人提供测试数据和可接受投稿的目录表单。第二周扩展负责人接只读分析，后端负责人并行开发投稿占位与额度事务。第三、四周集中联调目录投稿，其他清单能力按下表集成。12/04 按单平台最小样本评估，12/18 同时复核大批次分段调度。若投稿防重或恢复验收未通过，该版先交付已验收的只读能力，真实提交顺延到复测通过。

### 外链筛选交付安排

- **11/23–11/27 接口验证**由后端负责人查证免费 DR 端点、免费账号令牌、速率限制和展示署名要求。用获准账号查询一个测试域名并记录响应。根据验证结果确定自动查询或导入路径。

- **11/30–12/11 清单阶段**接入逐条选择、选择全部筛选结果、历史样本属性及最低 DR 筛选。管理员可导入经授权的域名、评分和观测日期。用缺失值、零分和跨页匹配验证筛选与批次快照。开放 API 接入取决于工作空间的供应商权限及展示许可。
- **01/04–01/15 投稿阶段**记录同入口历史样本，投稿后核验实际公开链接的 rel 属性。用历史样本与实际链接属性不同的页面验收，确保两次观测均可追溯。

### 影响日期的依赖

第一周由后端负责人核对系统模型服务的可用性、预算与 Gmail 单独授权条件。扩展负责人准备分别覆盖免登录、邮箱验证和 Google 登录的测试站点及账号。Excel 库的发行来源、许可与样表在清单阶段验证。外部授权或测试环境延期时，先完成已有条件的只读、清单和免登录流程，并在对应阶段重新估算受影响功能。Chrome 商店审核时间独立于安装包验收。
