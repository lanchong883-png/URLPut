# URLPut 本机版实施计划

## 基线和交付边界

- 代码基线为 GitHub `main` 的 `9f28eca`。视觉和交互基线为
  `75ea576` 的原型及配套说明。原型定义单页内依次出现的五个或八个编号区块，
  推广站点和外链清单可展开，启动前确认位于末尾。
  [交互说明][interaction] · [可点击原型][prototype]
- 从 Chrome 工具栏打开的右侧面板承担建批、任务、进度和结果。
  全页工作台提供备用入口。目录初始化、绑定、换绑、备份和恢复从设置进入，
  建批遇到失权时就地提示并保留草稿。
  [本机存储设计][storage]
- 同一 Chrome 配置共用本机工作空间。业务数据保存在用户选定的目录，
  核心流程在业务 API 和数据库停用时可操作。访问目标站点、公开核验和
  已配置的可选模型仍按各自的连接条件运行。
  [本机版规范与验收][acceptance]
- 「分析后执行」在同一批次接续到准备草稿、逐条批准和人工投稿。
  用户在目标站点完成登录、验证及发表。原型的模拟发表和可关闭的发表确认
  对应长期设计，本机版始终要求逐条批准。插件登录、云端共享、自动认证、
  自动发表及 Excel 排期沿用后续产品路线。
  [项目章程][constitution] · [产品需求][product]
- 旧的双人前后端排期从 [历史实施计划][previous] 查阅。本计划按阶段验收
  排序，日期待各阶段拆解、测试站点授权和目标 Chrome 环境确认后估算。

## 现状与证据

- 当前本机建批从单站选择和导入预览进入保存或「保存并开始分析」。
  目录控制出现在工作台内容中。撤权后工作台主体卸载，「新建批次」只剩
  目录相关操作。尚缺独立选用本机外链清单、跨站点快照及启动前确认。
  [侧栏基线提交][baseline]
- 2026-11-24 在 320 px 和 392 px 核对原型的模式切换、外链清空和清单
  返回焦点。同一宽度下，以解包构建直开 `sidepanel.html` 并模拟撤权，
  两次均复现上述缺陷。桌面 Chrome 的真实右侧面板验收仍待执行。
- 现有目录读写、逐行回执、公开核验和分段队列可复用。队列目前由工作台
  页面触发运行，已有浏览器配置内的 Web Lock 和手动续跑。跨站批次、
  关闭侧栏后的任务生命周期、独立执行控制及阶段复用需要实现和复验。
- 历史记录覆盖解包扩展回归、Linux 原生目录操作和 Ego Lite 真实站点回执。
  其中有独立游客验证的公开链接，也有平台已接收但等待公开的条目。
  历史清单的勾选与 Spec Kit 中的待验项应逐条对照构建、入口和测试环境。
  T010–T012 的 URLPut 内部投稿、跨批防重、核验及导出闭环仍待验收。
  [历史验收证据][acceptance] · [既有验收任务][tasks]

## 实施顺序与验收

### 第一阶段 · 交互基线、侧栏和目录（01–02）

1. **固定交互与视觉。** 在 320 px 和 392 px 记录六项导航、两个模式的区块、
   默认展开态、字段和启动条件、清单往返焦点及空态。保留基线版本的撤权截图，
   用「新建批次仅剩目录操作」标记回归用例。
   沿用浅灰紫底、固定顶栏、单列白色卡片、靛紫主按钮和卡片内列表滚动。
   验收两个宽度下的键盘焦点、长 URL、无横向溢出，以及加载、空、错误和禁用
   反馈。任务状态同时使用文字、进度数值和颜色。
2. **目录管理与就地恢复。** 把目录名称、授权状态、最近写入、初始化、绑定、
   换绑、备份和恢复移到侧栏设置入口。无绑定时从当前建批区块进入设置，
   原目录失权时直接重新授权。取消或拒绝可重试，成功回到原区块并恢复焦点和
   草稿。恢复原绑定与切换到另一个工作空间分别验收，切换后按新目录校验所选
   站点和清单。以空目录、已有 `URLPut-data-v1`、真实撤权、移动目录、备份
   恢复各走一遍。确认旧批次、原始行、回执和未完成队列可读，原目录保留，
   后续写入落到预期目录。换绑或备份遇到运行中的任务，按已有互斥约束提示
   并允许稍后重试。授权中断期间的待写回记录须能恢复，避免显示保存成功后丢失。

### 第二阶段 · 清单和五区块建批（03–05）

1. **让清单可维护、可复用。** 推广站点有稳定身份，支持搜索、查看、编辑和
   确认删除。同域名重新导入沿用原身份。外链支持保存多份有名称的清单，
   默认按文件名或序号命名，可搜索、查看、维护并导出单份或全部活跃外链。
   用 CSV、TXT、表格及网址粘贴验证新增、已有、重复和问题行。重复保留来源
   关联，问题 CSV 含原值、行号和原因。先区分解析通过与入口检查通过，入口
   不可用、超时或已退出活跃状态的行可追溯且不可选。外链检查由用户发起，
   走共用的只读请求槽。用过期记录复验活跃状态更新和历史快照。
2. **推广站点与外链选择。** 多选推广站点，每次批次选用一份已保存的清单，
   在该清单内多选活跃外链。用两个站点和两份清单验证切换、全选和清空。
   外链默认全选，站点默认由用户选择。搜索和筛选只更新可见项，
   「只选筛选结果」替换已有选择并涵盖未加载项，零匹配时将选择清空。
   首屏 5 条、后续每次追加 5 条，切换条件归首屏。验证站点和外链搜索、
   网站类型、价格、历史样本链接属性、DR 下限及 0 分与未知值。评分使用
   已授权的导入数据及来源日期。去清单补录或换清单后回到来源区块，
   保留适用草稿，可带回新站点或清单。
3. **执行方式、批次设置、启动前确认。** 仅分析依序显示「推广站点 → 外链清单
   → 执行方式 → 批次设置 → 启动前确认」。批次名称可选，每站候选上限进入
   预览计算。两个站点、每站上限三条的样本显示六个候选组合，并按同一候选
   范围核算待接收数。已有明确接收回执且仍待审核的组合计入已接收。
   零站点或零活跃外链禁止启动，返回修改后重算。启动遇到目标站点主机权限
   拒绝时保留确认区与草稿。用 100 站 × 1,000 条验证 100,000 组合的计数、
   分段调度和分页读取。

本阶段开始前先定下清单身份、原始来源行和旧批次读回方式。确认启动后以同一次
启动标识创建一个可恢复的批次并打开其详情。快照保存站点、候选、来源和配置，
后续编辑或删除清单不会改变已启动批次。首个可运行版本同时验证防重复启动、
入队与落盘的中断恢复、同配置多窗口共用请求槽，以及关闭侧栏后的持续执行。
从任务页重新打开同一批次可查看本轮进度、结果和 CSV。先通过这些路径，
再扩展任务管理。

### 第三阶段 · 任务、执行控制和结果（06–08）

1. **任务、历史和进度。** 任务页按创建时间显示批次，可按名称、编号、状态
   检索和分页。进行中进入进度，已完成进入结果。同一详情可切换全批次和
   单站，候选、已处理、待处理、已接收和有效数按各自条件核对。关闭再打开
   侧栏，仍能从历史进入同一批次。汇总跨批待确认项，显示站点、目标和原因。
2. **执行控制和恢复。** 在同一配置的两个窗口启动批次，并交叉触发清单检查、
   分析和回访，记录应用主动请求峰值为 1、请求间隔至少 2 秒、超时 15 秒和
   `Retry-After`。验证暂停暂缓调度、中断挂起并保存检查点、停止关闭自动
   执行，三者均可手动继续。分别关闭发起侧栏和整个 Chrome，核对后台生命周期、
   可恢复检查点和待回写状态。用正常、超时、429、页面关闭和需人工样本验证
   单条隔离、失败原因、待办释放执行槽、空闲无轮询。重启后已落盘项零重复，
   未完成项可续跑，同一阶段的重叠组合共享结果。任何结果不明的发表尝试仅
   回到原记录核验。
3. **结果入口与导出。** 页面分析得出可解释的终态后进入「已完成网站分析」。
   有明确公开证据的核验记录进入「已核验外链台账」，区分有效、明确失效和
   下线。待审核、初次核验不确定和待人工留在来源任务。后续回访暂时失败时，
   保留上次确定结论并记录本次失败。按当前站点和状态筛选导出，核对批次、
   原始 URL、来源行、预期与实际目标、证据和时间，兼容现有 CSV 前九列。
   分别核查两张结果表、来源任务及审核中的回执计数。

### 第四阶段 · 八区块配置和人工投稿（09–10）

1. **补齐执行模式配置。** 在「执行方式」与「批次设置」之间加入「投稿内容」、
   「认证与二次确认」「提交频率」。仅分析时隐藏三块，切回后恢复草稿。
   模板按分类预选默认项，允许多选，模板与混合策略无模板时禁用启动，
   纯 AI 隐藏模板区。快照保留配置、模板版本及实际文案来源，续跑复用已生成
   草稿。认证显示用户到官方入口处理的动作。现有模型连接测试与实际草稿
   生成分别验收，系统默认模型可用性单列核实。未配置、模型失败、缺资料
   或需认证，任务进入待确认并保留原因。
2. **先保全发表记录，再开放人工提交。** 主流程中逐条展示推广站点、目标页
   和草稿，批准或跳过。打开可投稿入口之前持久化对应尝试和唯一占位。
   分阶段复用以推广站点和规范化外链为键，最终发表防重按推广站点和
   已识别平台归并。用同平台不同 URL、重叠批次和共享托管域名样本核对边界。
   用测试时钟检查站点滚动 24 小时额度、跨批共享、单站覆盖、取最低有效上限、
   自动续跑开关和手动下一轮。Chrome 重开后按原策略恢复可执行项。
   额度占用后断线或回执未知时只核对原记录。
3. **完成授权站点闭环。** 在侧栏批准，用户在获授权站点手动提交，再回侧栏登记
   回执。公开后在 URLPut 内定位同一条发布记录和实际目标链接，导出并核对
   来源行与证据。重启后验证同一平台的重复候选被拦截。平台仍在审核时保留
   待公开项，分别记录接收、公开和有效三个结果。选择可控的小页面作为主样本，
   历史大页面另测读取上限下的待核实结论。

## 阶段验收与确认

- 每阶段跑相关自动化回归，并在目标 Windows 的桌面 Chrome 中加载同提交
  的扩展，从工具栏打开真正的右侧面板验收。涉及权限时用原生目录选择、
  撤权与目标站点主机授权。记录提交、Chrome 版本、入口、面板可见宽度、步骤
  截图及相关请求日志、CSV、目录或检查点证据。停用业务服务时核对业务 API
  请求为零，分别记录目标站点的只读访问。
- 直接打开 `sidepanel.html`、模拟权限、全页工作台、其他浏览器和站外独立公开
  核验作为补充证据。每个检查项按实际环境标注通过、未验证或阻塞。
- 进入跨模块开发前，以本计划拆出对应的 Spec Kit Specify 和 Plan，提交范围、
  验收标准、设计决策及兼容风险给用户确认。收到明确确认后再进入 Tasks、
  Implement 和 Converge。既有本机验收规格继续记录原验收证据。
