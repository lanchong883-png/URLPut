## 第一个提交与首周验收

1. 将正式侧栏接入定稿的导航和页面布局，先让「清单」进入已有推广站点及 CSV 导入流程。保留工作台原有调用路径，抽取可复用的 React 组件。用解包扩展检查 320 px 和 392 px。
2. 把所选工作空间、站点和上传文件传给已有解析及 API。导入一份包含有效、重复和无效网址的 CSV，核对每行结论、原始行号及站点归属。刷新后重新从 API 读取同一批记录。
3. 下载逐行台账，用第二个推广站点复核筛选和导出范围。提交时记录 Git 提交号、验证命令及尚待接入的功能。11 月 27 日的交付物是能重现这条流程的可安装 Chrome 内测包。

## 运行与验证

使用 Node.js 24。首次安装运行 `npm ci`。在两个终端分别启动 `npm run dev:api -- --local` 和 `npm run dev:extension`。本机 API 使用端口 4310，示例数据保存在 `.data/postgres`。运行 `npm run build` 后，在 Chrome 开发者模式加载 `apps/extension/.output/chrome-mv3`。

提交前运行 `npm run check`、`npm test` 和 `npm run build`。扩展冒烟测试通过 `npm run test:extension` 启动独立数据库和服务，需要可用的 Chromium 和空闲的 4310 端口。交接时 Node.js v24.22.1 下的 `npm test` 通过 5 项测试。生产数据库、Supabase 配置和扩展环境变量见 [README](../README.md)。

## 关键验收约定

- 清单先显示 5 条，滚动追加。筛选外链后点「只选筛选结果」才替换选择。空 DR 和 0 分分别保存，真实 DR 接口的资格、限流及展示许可待核实，首周试用可用导入值。
- 仅分析共五步，直接产出只读结果。分析后执行共八步，模板或 AI 加模板至少选一份，纯 AI 可直接启动。批次保存创建时的站点、外链、文案策略和模板版本。
- 执行前检查跨批次重复及站点的滚动 24 小时额度。「每条投稿都先让我确认」要求用户逐条批准。提交后断网走只读核验。Chrome 保存或更新站点密码，URLPut 记录非秘密账号标识和状态。
- 按现有两名工程师与授权测试站到位的假设，11 月 27 日交首个安装包，12 月 4 日试用真实只读分析，12 月 18 日试用受控目录站投稿。完整范围预计 2027 年 2 月 12 日验收。
