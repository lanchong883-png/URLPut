# 本机存储与结果报告

## 范围

首版以单个 Chrome 浏览器配置为数据边界。用户可在设置中选择本机数据目录，推广站点、导入清单、任务、证据和结果都保存在该目录。扩展的浏览器存储用于加速显示和恢复未写入目录的记录。扩展可以在 Fastify、PGlite 和 PostgreSQL 全部停止时管理清单、恢复已保存的任务、浏览结果和导出。加载待分析网页和核验公开外链仍需要访问对应目标站点。

## 用户配置数据目录

- 在扩展设置页提供「选择数据目录」和「更改目录」。用户通过浏览器的目录选择器授权读写。扩展展示目录名称、授权状态和最后写入时间。关闭或重启 Chrome 后先检查授权，权限失效时提示用户重新授权。
- 目录内使用带格式版本的清单和按批次分段的文件保存业务数据。已核验台账和网站分析结果分别存放，可从设置页或结果页导出 CSV。目录文件保留可恢复的源数据，CSV 用于查看和分享。
- 数据目录是持久化副本。IndexedDB 保存可重建的索引和尚待写回的增量。侧栏搜索、滚动和切换标签从内存或索引读取。后台在阶段边界写入已完成的文件段，再更新清单。同一配置的多个窗口通过同一写入协调路径提交。重启时核对清单和待写回记录，续写未完成的文件段，避免重复入表。
- 目录未选定、被移动或暂时失去授权时，待写回记录留在浏览器并标明「待保存到目录」。重新授权后继续写回。涉及外部投稿的动作须先持久化发表意图和唯一占位。无法确认持久化时保持暂停。
- 更改目录时让用户选择迁移数据或打开已有 URLPut 目录。校验新目录和文件格式后切换，保留原目录。首版支持一个 Chrome 配置写入同一目录，浏览器配置间使用手动备份与恢复。

## 两个结果入口

| 入口 | 入表条件 | 展示字段 |
| --- | --- | --- |
| 已核验外链台账 | 完成公开核验且有明确证据 | 推广站点、平台、公开记录网址、预期目标、实际链接与属性、核验时间、证据和结论。有效、链接失效、明确下线等可按结论筛选 |
| 已完成网站分析 | 页面分析已得到可解释的终态 | 来源与最终网址、可访问性、网站分类、投稿入口、是否登录、费用、必填资料、限制条件、证据、分析时间和下一步。无法读取时给出具体结论。无法判断的字段显示未知 |

已接收待审核、待核验、处理中、输入错误和待人工归入任务或导入预览。核验超时继续保留任务状态，直到取得确定证据。只读分析的结果只进入网站分析。两张结果表分别支持 CSV 导出，按当前筛选导出。结果保留必要证据摘要和来源链接，凭据及完整验证链接留在浏览器认证流程中。

## 存取与恢复

- 小型偏好使用 `chrome.storage.local`。清单、任务、去重记录和结果在 IndexedDB 中建立本机索引。首次打开结果页时按推广站点、状态和时间索引读取当前页。
- 侧栏使用内存中的当前页响应搜索输入和视图切换。搜索确认、筛选变动和翻页按需读取本机索引。后台提交后通过扩展消息通知侧栏刷新受影响的记录，无需定时轮询。
- 导入在浏览器内解析和预览，确认后一次事务保存该批次。分析和核验把零散进度留在内存，在可恢复的阶段边界合并写入。结果、必要状态、检查点和待写回标记在同一 IndexedDB 事务提交。目录写入成功后清除待写回标记。
- 同一浏览器配置中的多个窗口共享同一 IndexedDB。任何可能产生外部投稿的最终动作仍须先原子写入唯一尝试和发表意图，并确认可恢复。重启后对已有意图只做只读核验。跨设备共享、防重和同步退出本机首版范围。
- 旧 Fastify 台账继续可读，等本机路径验证后提供显式迁移。迁移以原批次 ID 和原始行标识去重。只有具备相应证据的历史记录才进入两张结果表。需在替换默认入口前验证迁移可重试、数据保留和手动备份恢复。

## 单任务串行队列

同一个 Chrome 配置共用一个执行槽，覆盖所有窗口、目录和批次。批次按入队顺序等待，批内按原始行序一次处理一个 URL。切换侧栏或重复点击启动继续使用现有队列。导入和浏览台账不会自动访问外链。

- 待处理项按批次分段保存在用户目录，检查点记录当前批次和下一个行号。执行器只加载当前小段和当前 URL 所需的数据。侧栏分页显示进度。HTML、截图和响应正文处理完即释放，持久化时仅保存所需证据。
- 浏览器级互斥锁覆盖领取、执行及检查点提交。上一个 URL 的请求结束、资源释放、结果和检查点保存完成后，才开始下一个 URL。重启从持久化检查点恢复。已经记录发表意图的任务仅进入只读核验。
- 同一时刻最多一个应用主动发起的外链请求。初始参数采用请求间隔至少 2 秒、只读请求超时 15 秒。遇到 429 遵守 Retry-After，缺少有效提示时暂停该站点并等待恢复。发表动作自动重试次数为零。网页自行加载的子资源单独统计，验收时检查标签页数量和子资源流量。
- 等待人工或限流时保存状态并释放执行槽，其他可运行项依入队顺序继续。空队列和全部等待时停止调度。通过入队、人工恢复或到期的单次唤醒继续执行。
- 验收时从两个窗口同时加入两个批次，记录执行起止、请求和内存。验证峰值运行 URL 数为 1，重复启动不重复领取，长队列不会同时加载所有页面，空闲期间无轮询。另测超时、429、页面关闭和浏览器重启。

### 单条异常与批次收尾

- 每个自动执行阶段设置截止时间。阶段超时、页面关闭、单条失败或需要用户操作时，取消该条请求并隔离迟到回调。将任务 ID、推广站点、URL、来源行、失败阶段、时间、原因、最近检查点及建议动作保存到本机，再释放执行槽，继续下一条可运行任务。
- 批次中最后一条可运行任务结束时，若仍有问题，状态显示「本轮结束，有待处理项」。任务页集中列出完成数和待处理数，并支持逐条查看原因。所有任务均遇到问题时同样生成清单，停止轮询。问题清单在重启后仍可查看。
- 用户可按提示补资料、授权、从检查点恢复，或确认跳过并记录原因。恢复只将所选任务放回队尾；连续点击按任务 ID 去重。若已经记录发表意图或提交结果不明确，恢复动作仅允许核验已有记录。
- 验收样例：同批依次加入一个超时 URL、一个需要登录的 URL 和一个正常 URL。正常项应完成，本轮结束后应列出前两项及各自的解决方法。重启后修复登录项，仅该项重新排队；超时项保留待处理，已完成项维持原结果。

## 交付顺序与验收

1. 将现有推广站点、CSV、TXT 导入和批次历史接到本机存储。用已有测试数据验证旧批次迁移、可配置数据目录和站点隔离。
2. 在授权样例站接通只读分析，保存终态、证据和时间。实现网站分析表与 CSV 导出。
3. 接通公开外链只读核验和已核验外链台账。覆盖有效、明确失效、待审核和无法确认四种结果。
4. 在解包扩展中停止本地 API 和数据库，验证导入、侧栏重开、浏览器重启、筛选和导出。通过请求记录验证日常路径对业务 API 的调用次数为零，通过本机写入统计验证输入、滚动和空闲期间无周期写入。验证两个窗口的更新可见性、阶段中断恢复、目录换绑、权限失效后续写，以及数据迁移可重试。
