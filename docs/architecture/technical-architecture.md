# URLPut 技术架构

依据 [产品需求与详细设计](../requirements/product-requirements.md)。首个交付是 Chrome 扩展内的站点选择、导入、只读分析和逐行报告。后续逐步接入投稿、人工队列和回访。

## 技术选型

| 层 | 建议方案 | 复用范围 |
| --- | --- | --- |
| 扩展构建 | WXT + TypeScript | 自动组织 MV3 入口、生成 manifest、支持开发加载与打包。权限和扩展 ID 仍需项目显式配置。 |
| 前端界面 | React | 侧边栏显示队列，扩展全页承载导入预览和报告，两处复用组件。首版无需独立 Web 管理站。 |
| 浏览器运行 | Chrome MV3 API、IndexedDB（idb） | 通过 Service Worker、扩展消息和 alarms 调度，用 IndexedDB 保存可恢复的本机检查点。 |
| API | Node.js 24 LTS + Fastify + TypeScript | 单体 API 提供访问控制、导入确认、任务和报告。复用 Fastify 的请求生命周期和日志，使用 Zod 校验边界数据。 |
| 数据 | PostgreSQL + Drizzle + node-postgres | 复用迁移、事务、唯一约束和持久化。关键事务用集成测试覆盖。 |
| 登录 | Supabase Auth + 官方 SDK | 复用身份、会话和登录流程。Fastify 验证访问令牌并查询业务成员关系。托管方式和区域待确认，本地可用 Supabase CLI 进行认证联调。 |
| 文件处理 | csv-parse、csv-stringify；SheetJS CE 候选 | CSV 解析和序列化复用现有库。Excel 优先验证一个库覆盖 .xls/.xlsx 导入及 .xlsx 导出。SheetJS 官方下载源本次未能访问，待验证可信版本、完整性和样表后锁定。 |
| 页面分析 | DOM API、tldts；Mozilla Readability 可选 | DOM 读取实际控件，tldts 提供域名线索。需要抽取独立指南时，Readability 处理文档副本。 |
| 验证 | Vitest、Fastify inject、Playwright、真实 PostgreSQL | 单测覆盖解析和状态转换，集成测试覆盖 API 和并发约束，扩展端到端在本地测试站运行。 |

建议使用 npm workspaces，保留一个锁文件。新增依赖前验证许可、构建目标兼容性和安全更新渠道，CI 使用锁文件安装。

## 代码和运行边界

| 目录 | 职责 |
| --- | --- |
| `apps/extension` | WXT 入口、React 页面、后台调度、内容脚本和本地持久化。 |
| `apps/api` | Fastify 路由、认证、业务授权、Drizzle 数据库操作和迁移。 |
| `packages/contracts` | Zod 请求及响应、报告字段定义、共享状态枚举。 |
| `packages/import` | 导入解析、字段映射、URL 规范化及逐行反馈，可在扩展侧预览并在服务端复用业务校验。 |

导入在扩展侧解析，上传用户确认的行及来源元数据。API 重新校验数据、资格及大小限制，并在一个事务内保存批次、原始行和候选关联。批次确认由客户端生成幂等键，避免网络重试重复建批。报告按原始行输出，工作台和导出共用前七列、排序标识和结论字典。导出处理可被电子表格解释为公式的输入。

扩展只为用户选定的站点请求所需主机权限。后台校验内容脚本的发送来源、标签页和任务对应关系。内容脚本限于页面读取、填表与用户已授权的动作。第三方登录在人机界面完成，应用账号与 Gmail 授权各自独立。正式上线前验证扩展 ID、回调地址、登录和会话刷新在打包构建中可用。后端管理密钥不进入扩展包。

首版仅凭导入值做 URL 格式和明显非公开地址校验，实际访问时再次校验最终地址。若后续引入服务端外部读取，逐跳检查 DNS 和重定向，限制私网、回环和保留地址，并设置网络超时及响应大小上限。业务服务日志过滤令牌、密码、验证码和完整激活链接。

## 持久化与去重

PostgreSQL 保存工作空间、成员、推广站及其资料版本、导入批次、原始行、候选、平台及别名、任务、唯一尝试和事件。业务查询按已认证成员关系限制工作空间，所有跨实体关联核对所属工作空间。扩展的 IndexedDB 保存本机进度、待同步事件和恢复所需的任务信息。API 保存跨设备共享的台账和最终尝试状态。

1. **导入时**，在批次内按规范化候选合并，每条原始行保留原值、来源和序号。同一行的展示 URL 和已知投稿入口分别保留。
2. **分析前**，按后端确认的平台 ID 查询历史、人工补录和停用记录。公共后缀及域名只用于辅助匹配，共享托管域名上的独立站点以已确认身份区分。
3. **发表前**，后端短事务校验权益、占用 `(promotion_site_id, platform_id)` 唯一名额并写入发表意图。冲突关联原记录。平台无法明确归属时暂停发表，别名变更需和占位使用一致的平台身份规则。

只有首次获得当前任务发表资格的执行方才能进入最终动作。重试或其他设备查询可取得现有记录，不会再次获得点击资格。写入发表意图后发生断网、崩溃或无回执时进入只读核验，保留名额。后端不可用时暂停最终发表。

后台用有限并发执行并在每步保存检查点，由 Chrome 启动事件、alarms 和用户动作唤醒。浏览器关闭后停止浏览器动作，重启从检查点继续。需验证码、授权或资料的任务单独挂起。首版使用扩展本地调度与后端任务记录，后续若需要独立后台回访，再评估 PostgreSQL 队列库。

## 首个交付的实现顺序

1. 建立 WXT、Fastify 和 PostgreSQL 骨架，接通锁文件安装、类型检查和 CI。用解包扩展验证侧边栏、报告页和后台消息。
2. 用认证和成员关系打通工作空间与推广站查询。测试跨工作空间读取、批次创建和任务查询被拒绝。
3. 做 CSV 与粘贴导入。验证表头、列映射、引号内换行、重复候选、无效地址及原始行追溯。再补 TXT 与 Excel，用等价清单验证四种输入结果一致。
4. 打通只读分析与逐行报告。用本地可控表单验证无写入、缺字段逐条反馈和后台休眠后续跑。
5. 相应阶段再接联调投稿。数据库测试覆盖两个并发批次最多一次尝试，扩展测试覆盖响应丢失和进程重启后只读核验。

需要自行实现的核心逻辑包括投稿入口和控件含义识别、平台身份和历史归并、尝试与恢复状态转换、核验证据及报告口径。这些规则直接对应验收用例。

### 接入顺序与验收

| 顺序 | 接入位置与复用方式 | 验收用例 |
| --- | --- | --- |
| 1. CSV 与表格粘贴 | 在 `packages/import` 接入 `csv-parse` 的浏览器构建。两种入口共用分隔记录解析与列映射，保留解析得到的原始记录位置。分隔符识别不确定时允许用户确认。 | UTF-8 BOM、逗号／分号／制表符、引号内换行、有无表头、坏行反馈，以及重复候选仍可追溯到所有原始行。 |
| 2. 域名线索 | 在平台身份解析模块接入 `tldts`，开启私有公共后缀识别。保留完整主机名和 URL，用域名结果辅助查找候选平台，平台 ID 由业务规则确认。 | 普通子域、国际化域名、同一共享托管后缀下的独立站、确认过的别名和重定向均有用例。 |
| 3. CSV 报告 | 在报告导出入口接入 `csv-stringify`，沿用工作台的七列定义和原始行序号。对可能被表格软件解释为公式的文本启用转义，并以样表验证。 | 工作台与 CSV 列名和顺序一致，成功、失败、待审核和重复行均保留。包含换行和公式前缀的文本能安全导出。 |
| 4. Excel | 先验证官方 SheetJS CE 固定版本的下载来源和锁文件完整性，再用同一个库读 `.xls`、读写 `.xlsx`。Excel 和 CSV 共用后续列映射、校验及台账逻辑。 | 工作表选择、显示文字背后的超链接、四类等价输入、导出前七列对齐，以及大文件限制和损坏文件反馈。 |
| 5. 指南正文 | 只有只读分析需要提取独立指南时才引入 Readability，在文档副本上提取。 | 指南正文能定位费用或资料要求的证据，表单读取和原页面保持原状。 |

代码接入时通过包管理器引入依赖并提交锁文件。扩展端验证依赖能随 MV3 一起构建，CI 通过冻结安装、类型检查和样表测试验证可复现。每个库在对应功能首次使用时引入。Automa 和 seo-ai-link 保留为流程参考。

库负责通用格式和域名解析。URLPut 负责来源行追溯、已确认的平台别名、跨批次唯一尝试、状态恢复和证据口径。先用 CSV 和粘贴把「预览 → 确认 → 台账」跑通，Excel 验证与接入随后进行。

## 可配置 AI 服务

扩展按「本地模型」和「自建模型服务」保存两份配置。每份包含 API 基础地址、模型名，以及分析和文案两个独立开关。首版采用 OpenAI Chat Completions 兼容协议，例如 Ollama 本地接口和团队自建 HTTPS 网关。扩展只在用户点击测试后请求相应主机权限并发送固定测试消息。模型密钥保留在扩展的浏览器会话存储中，并绑定到配置地址。

后续分析和文案功能接入时，共用同一服务配置，以两个开关分别控制调用。导入和规则匹配无需配置模型。当前功能验证范围为配置保存、切换和连接测试。
