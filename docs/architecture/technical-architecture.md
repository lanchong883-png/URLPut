# URLPut 技术架构

本文依据 [产品需求与详细设计](../requirements/product-requirements.md) 和 [侧边栏交互设计](../design/workbench-interaction.md)。首个交付分阶段打通站点选择、导入、只读分析和逐行报告，再接入投稿、人工队列及回访。

## 技术选型

| 层 | 建议方案 | 复用范围 |
| --- | --- | --- |
| 扩展构建 | WXT + TypeScript | 自动组织 MV3 入口、生成 manifest、支持开发加载与打包。权限和扩展 ID 仍需项目显式配置。 |
| 前端界面 | React | Chrome 侧边栏承载日常任务和配置。当前扩展全页承载导入工作台，完整报告可按需打开。组件可复用，无需独立 Web 管理站。 |
| 浏览器运行 | Chrome MV3 API、IndexedDB（idb） | 通过 Service Worker、扩展消息和 alarms 调度，用 IndexedDB 保存可恢复的本机检查点。 |
| API | Node.js 24 LTS + Fastify + TypeScript | 单体 API 提供访问控制、导入确认、任务和报告。复用 Fastify 的请求生命周期和日志，使用 Zod 校验边界数据。 |
| 数据 | PostgreSQL + Drizzle + node-postgres | 复用迁移、事务、唯一约束和持久化。关键事务用集成测试覆盖。 |
| 登录 | Supabase Auth + 官方 SDK | 复用身份、会话和登录流程。Fastify 验证访问令牌并查询业务成员关系。托管方式和区域待确认，本地可用 Supabase CLI 进行认证联调。 |
| 文件处理 | csv-parse、csv-stringify 和候选库 SheetJS CE | CSV 解析和序列化复用现有库。Excel 优先验证一个库覆盖 .xls/.xlsx 导入及 .xlsx 导出。SheetJS 官方下载源本次未能访问，待验证可信版本、完整性和样表后锁定。 |
| 页面分析 | DOM API、tldts，可选 Mozilla Readability | DOM 读取实际控件，tldts 提供域名线索。需要抽取独立指南时，Readability 处理文档副本。 |
| 验证 | Node.js 测试运行器、Fastify inject、Playwright、真实 PostgreSQL | 复用现有单测、API 注入测试和扩展冒烟测试。跨批次并发和恢复须用真实 PostgreSQL 及本地可控测试站验收。 |

建议使用 npm workspaces，保留一个锁文件。新增依赖前验证许可、构建目标兼容性和安全更新渠道，CI 使用锁文件安装。

## 代码和运行边界

| 目录 | 职责 |
| --- | --- |
| `apps/extension` | WXT 入口、React 页面、后台调度、内容脚本和本地持久化。 |
| `apps/api` | Fastify 路由、认证、业务授权、Drizzle 数据库操作和迁移。 |
| `packages/contracts` | Zod 请求及响应、报告字段定义、共享状态枚举。 |
| `packages/import` | 导入解析、字段映射、URL 规范化及逐行反馈，可在扩展侧预览并在服务端复用业务校验。 |

## 批次、清单与导出

扩展侧用 `packages/import` 解析数据和保留源信息。正式清单在用户点击检查后提交新项，API 重校验格式、权益和大小限制。站点按工作空间和规范化域名归并，外链按工作空间和规范化 URL 查询共享候选。同一导入可引用已有候选，重复原始行保留出处，检查结果区分新增、已有、清单内重复及问题。重试检查或建批用幂等键避免重复保存。入口无法确认可用时不进入活跃清单。

批次保存推广站点、资料版本、候选集合、策略及内容模板快照。删除站点后，新批次排除该站点，历史仍引用原身份及资料。站点资料的多张文件与图片 URL 统一关联到资料版本，CSV 仅导入文字和 URL，文件从站点编辑上传。历史导出和活跃清单独立读取。

批次以站点集合与候选集合为输入，按段生成并调度组合。100 个站点 × 1,000 条外链时，侧栏只请求所需页，首屏 5 条、后续每次 5 条。外链默认全选，可逐条勾选、清空，或用「只选筛选结果」替换当前选择，包括尚未加载的匹配项。支持组合搜索、网站类型、价格、历史样本链接属性及最低 Ahrefs DR。批次按选中的活跃外链和每站上限建立快照。启动摘要及任务统计从集合和计数生成。

| 导出 | 读取与字段 |
| --- | --- |
| 任务报告 CSV 或 Excel | 按批次或站点读取快照，工作台与下载共用最前九列、排序标识和结论字典。前七列沿用原协议，第八、九列为「推广站点」「推广站点网址」。原始行在不同站点各保留结果。 |
| 活跃外链 CSV | 按一份或全部清单查询活跃外链，包含清单名称、来源类型、来源行、外链 URL、网站域名和网站类型。 |
| 问题行 CSV | 包含原始行号、原值和原因，供修正重导。 |

所有电子表格导出统一处理可能被解释为公式的值。

## 执行权限与页面读取

扩展只为用户选定的站点请求所需主机权限。后台校验内容脚本的发送来源、标签页和任务对应关系。内容脚本限于页面读取、填表与用户已授权的动作。第三方登录在人机界面完成，应用账号与 Gmail 授权各自独立。正式上线前验证扩展 ID、回调地址、登录和会话刷新在打包构建中可用。后端管理密钥不进入扩展包。

首版仅凭导入值做 URL 格式和明显非公开地址校验，实际访问时再次校验最终地址。若后续引入服务端外部读取，逐跳检查 DNS 和重定向，限制私网、回环和保留地址，并设置网络超时及响应大小上限。业务服务日志过滤令牌、密码、验证码和完整激活链接。

## 持久化与去重

PostgreSQL 保存工作空间、成员、推广站及其资料版本、导入批次、原始行、候选、平台及别名、任务、唯一尝试和事件。业务查询按已认证成员关系限制工作空间，所有跨实体关联核对所属工作空间。扩展的 IndexedDB 保存本机进度、待同步事件和恢复所需的任务信息。API 保存跨设备共享的台账和最终尝试状态。

1. **导入时**，在批次内按规范化候选合并，每条原始行保留原值、来源和序号。同一行的展示 URL 和已知投稿入口分别保留。
2. **分析前**，按后端确认的平台 ID 查询历史、人工补录和停用记录。公共后缀及域名只用于辅助匹配，共享托管域名上的独立站点以已确认身份区分。
3. **发表前**，后端短事务校验权益、占用 `(promotion_site_id, platform_id)` 唯一名额并写入发表意图。冲突关联原记录。平台无法明确归属时暂停发表，别名变更需和占位使用一致的平台身份规则。

只有首次获得当前任务发表资格的执行方才能进入最终动作。重试或其他设备查询可取得现有记录，不会再次获得点击资格。写入发表意图后发生断网、崩溃或无回执时进入只读核验，保留名额。后端不可用时暂停最终发表。

后台用有限并发执行并在每步保存检查点，由 Chrome 启动事件、alarms 和用户动作唤醒。浏览器关闭后停止浏览器动作，重启从检查点继续。需验证码、授权或资料的任务单独挂起。首版使用扩展本地调度与后端任务记录，后续若需要独立后台回访，再评估 PostgreSQL 队列库。

## 首个交付的实现顺序

1. 建立 WXT、Fastify 和 PostgreSQL 骨架，接通锁文件安装、类型检查和 CI。用解包扩展验证侧边栏、报告页和后台消息。
2. 用认证和成员关系打通工作空间与推广站查询。测试跨工作空间读取、批次创建和任务查询被拒绝。
3. 做 CSV 与粘贴导入。验证表头、列映射、引号内换行、重复候选、无效地址及原始行追溯。再补 TXT 与 Excel，用等价清单验证四种输入结果一致。
4. 打通只读分析与逐行报告。用本地可控表单验证无写入、缺字段逐条反馈和后台休眠后续跑。
5. 相应阶段再接联调投稿。数据库测试覆盖两个并发批次最多一次尝试，扩展测试覆盖响应丢失和进程重启后只读核验。

需要自行实现的核心逻辑包括投稿入口和控件含义识别、平台身份和历史归并、尝试与恢复状态转换、核验证据及报告口径。这些规则直接对应验收用例。

### 接入顺序与验收

| 顺序 | 接入位置与复用方式 | 验收用例 |
| --- | --- | --- |
| 1. CSV 与表格粘贴 | 在 `packages/import` 接入 `csv-parse` 的浏览器构建。两种入口共用分隔记录解析与列映射，保留解析得到的原始记录位置。分隔符识别不确定时允许用户确认。 | UTF-8 BOM、逗号／分号／制表符、引号内换行、有无表头、坏行反馈，以及重复候选仍可追溯到所有原始行。 |
| 2. 域名线索 | 在平台身份解析模块接入 `tldts`，开启私有公共后缀识别。保留完整主机名和 URL，用域名结果辅助查找候选平台，平台 ID 由业务规则确认。 | 普通子域、国际化域名、同一共享托管后缀下的独立站、确认过的别名和重定向均有用例。 |
| 3. CSV 报告 | 在报告导出入口接入 `csv-stringify`，沿用工作台的前九列定义和原始行序号。对可能被表格软件解释为公式的文本启用转义，并以样表验证。 | 工作台与 CSV 列名和顺序一致，成功、失败、待审核和重复行均保留。包含换行和公式前缀的文本能安全导出。 |
| 4. Excel | 先验证官方 SheetJS CE 固定版本的下载来源和锁文件完整性，再用同一个库读 `.xls`、读写 `.xlsx`。Excel 和 CSV 共用后续列映射、校验及台账逻辑。 | 工作表选择、显示文字背后的超链接、四类等价输入、导出前九列对齐，以及大文件限制和损坏文件反馈。 |
| 5. 指南正文 | 只有只读分析需要提取独立指南时才引入 Readability，在文档副本上提取。 | 指南正文能定位费用或资料要求的证据，表单读取和原页面保持原状。 |

代码接入时通过包管理器引入依赖并提交锁文件。扩展端验证依赖能随 MV3 一起构建，CI 通过冻结安装、类型检查和样表测试验证可复现。每个库在对应功能首次使用时引入。Automa 和 seo-ai-link 保留为流程参考。

库负责通用格式和域名解析。URLPut 负责来源行追溯、已确认的平台别名、跨批次唯一尝试、状态恢复和证据口径。先用 CSV 和粘贴把「预览 → 确认 → 台账」跑通，Excel 验证与接入随后进行。

## 可配置 AI 服务

目标界面默认选择系统自带模型，服务连接由系统提供。选择本地模型时才显示 API 基础地址、模型名和可选密钥。分析与文案共用同一模型。首版采用 OpenAI Chat Completions 兼容协议，支持本机 HTTP 和自建 HTTPS 网关。扩展只在用户点击测试后请求相应主机权限并发送固定测试消息。模型密钥保留在扩展的浏览器会话存储中，并绑定到配置地址。

后续分析和文案功能接入时，共用同一服务配置，根据批次设置决定调用。导入和规则匹配无需配置模型。当前功能验证范围为配置保存、切换和连接测试。

正式任务保存内容策略、候选模板版本和最终草稿。默认模板按分类独立维护，选模板或 AI 加模板时先过滤入口类型，再从已选的同类模板随机取一份，无命中再用已选通用文案。AI 独立拟写直接根据当前网页和站点资料生成。AI 接收必要的主题、字段约束和可共享品牌资料。草稿已生成后，安全续跑复用原版本。用户可将草稿编辑为内容模板并替换站点变量。内容模板属于用户文案库，表单字段映射由外链知识库独立管理。


## 跨批次执行状态

在 PostgreSQL 按 `workspace_id + promotion_site_id + normalized_url + stage` 保存共享处理记录，关联各批次候选。保留路径和查询参数，移除片段，平台身份归并沿用独立规则。进入执行前通过唯一约束和条件更新认领。认领事务只管理状态，浏览器处理在事务外运行。竞争方读取已有终态或等待当前认领结果。

每条完成后用认领令牌有条件写回结论，并在同一事务追加状态事件及原批次引用。其它批次根据共享状态更新行级进度，事件订阅或增量轮询可以重复送达。重复结果关联原记录，不占用当天额度。最终发表在同一短事务校验「推广站点 + 平台」唯一名额和该站点的滚动 24 小时额度，并写入发表意图。额度在工作空间内跨批次共享，多条有效限制取最低值。

执行阶段保留开始、提交前、已持久化发表意图、结果及时间。只有确认未进入发表阶段且满足重试时间的临时失败才能重新认领。认领超时且发表状态不明时进入只读核验。旧工作者恢复后必须持有效令牌才可推动状态。暂停暂缓调度，中断挂起，停止关闭自动续跑。三种人工动作均保留检查点供继续。日任务按额度和下次可执行时间恢复，禁止因补跑而突破滚动窗口。


## 外链模板知识库与活跃清单

Fastify 在工作空间成员权限下提供两组 API。模板存 PostgreSQL，身份键包含工作空间、外链页面来源（协议、主机和端口）、入口类型、规范化语言与结构摘要，页面路径不参加匹配。结构摘要包含表单动作来源、方式、字段名称、类型、标签、必填、长度和选项。浏览器仍以当前表单的动作地址和字段为准。命中时返回版本和字段映射，未命中由执行端重新识别并在验证后保存。映射同内容重试沿用版本，内容更新保留旧版本。库中只保存字段用途和结构，实际站点资料在执行时读取。

活跃清单按工作空间和规范化 URL 保存最新检查结果。查询只返回最近 30 天内确认活跃的外链。待复查查询返回 7 天未复查的条目，包括曾下线的入口，以便发现恢复。较晚送达的旧检查不会覆盖新结果，同一时间的冲突优先保留不可用结果。检查回传方应通过页面入口、投稿条件和已有结论判定可用性，网络响应成功本身不足以确认。后端已提供查询和写回接口，浏览器扫描和定时复查执行器尚待接入。面向清单的明细还需接入平台网站类型和来源行，入口类型单独用于执行及知识库匹配。

## 第三方认证与人工续跑

工作空间内维护邮箱账号、Google 账号选择和默认密码方案引用，并与推广站点的对外联系邮箱分开。批次保留认证策略。Google 登录经目标站的官方入口和浏览器会话处理，确认实际账号与批次策略一致。应用登录、目标站 Google 登录和 Gmail 查询独立授权。Gmail 查信按收件人、发件人、域和时间匹配，存在歧义时转人工。

普通登录优先使用 Chrome 针对同源及同一账号匹配的已保存密码，包括 Google 生成并同步的站点密码。登录、手动切换密码方案、找回和二次验证发生在浏览器或目标站。扩展只记录认证方式、目标来源、非秘密账号标识、可信状态、原因和检查点。密码、验证码、Cookie 和完整验证或重置链接不得进入 URLPut 的持久化、日志、模型请求或导出。密码保存及更新由 Chrome 原生界面和用户完成。扩展仅提示用户确认或继续。

认证任务区分已注册待验证、密码错误、账号不匹配和验证通过。密码错误时保留注册记录和原任务，用户通过官方找回流程重新登录。系统核对同一账号、页面来源和所需验证信号后恢复。首次通过可由用户确认保存密码，重置后同样可确认更新。未核对通过前只保留待办。多选检查逐条复核账号与页面信号，付费、回链、发表许可和密码保存各自需要单条确认。

### 链接属性与域名评分

正式执行读取同入口样本中指向推广目标的锚点，记录 rel 标记、样本网址与观察时间。nofollow、sponsored、ugc 可同时存在，缺少有效样本记为未知。Dofollow 表示样本链接没有上述限制标记。发布后读取实际公开页的对应链接，独立保存核验结果。

Ahrefs DR 是域名级第三方指标，记录评分、提供方、域名和观测日期。可导入经授权的评分，或在账号具备 Ahrefs API v3 权限后由后端使用令牌查询并按域名缓存。无授权、额度耗尽或无数据时保留带日期的历史值或显示未知。原型仅演示数据与筛选。

免费 DR 接口候选为 `GET /v3/public/domain-rating-free`，与 Site Explorer 的评分接口分开评估。上线前对照 Ahrefs 官方端点文档与 Domain Rating License，验证免费账号的令牌资格、请求参数、限流、缓存和向客户展示数据的权限。若条款要求署名，在评分旁展示可点击的「Domain Rating by Ahrefs」。验证通过后优先由管理员在后端接入。

DR 授权按工作空间管理。管理员可导入获准使用的数据，或在供应商套餐及许可覆盖团队使用时配置一次后端连接。成员共享有权限查看的评分，无需输入个人令牌。没有接口或数据来源时，DR 为未知，其他筛选和任务照常可用。跨客户提供评分须另行确认供应商的数据展示及分发条款。
