# Chrome 外链提交助手 · 产品需求与详细设计

版本：V1.0 ｜ 面向产品、开发和测试

## 1. 目标与边界

客户只安装一个 Chrome 插件，选择一个或多个要推广的网站，导入共享外链清单，启动后离开侧边栏。插件完成历史查询、页面分析、填写、提交、验证和逐行报告。Chrome 关闭时保存进度，下次打开后恢复。单条任务等待用户时，其他任务继续。

同一推广站在同一外链平台最多进行一次投稿尝试。常规任务优先使用本地规则，客户无需配置字段。AI 分析和文案生成分别可关闭。按站点售卖授权时，后端校验工作空间、域名和权益；套餐、回访间隔与 AI 预算可配置。

## 2. 用户流程与界面

1. 登录插件，选择工作空间。管理推广站点清单，勾选参加本批次的站点。清单页支持搜索和维护推广站点及命名外链清单。可确认删除推广站点，已启动批次仍保留原站点快照。推广站点支持通过多列 CSV 批量导入站点资料。
2. 首次录入品牌资料、允许推广的链接及语言版本，生成或手工保存通用内容。
3. 导入一份外链清单供选中的站点共用。在预览中检查列映射、合并项和错误行，确认每站使用上限和组合总数。新建批次可跳转到清单补充站点或外链。清单统一处理录入和导入，逐行核对新增、已有、重复及错误，站点名称由域名生成。点击检查即导入新增的有效项，自动生成外链清单名称，问题行可下载 CSV。返回时保留批次草稿，并可带回选中的站点或外链清单。按当前外链清单展示每站总外链数、已提交与待提交数，并支持筛选有待提交外链的站点。
4. 选择「仅分析」或「分析后执行」。批次分别记录是否允许注册、建档和正式发表，以及评论数量、字数和 AI 预算。允许为站点单独配置滚动 24 小时的提交尝试上限，同站点跨批次共享额度，可启用每日续跑。
5. 在侧边栏查看全部站点或单个站点的进度和当前平台。验证码、缺资料或需本人授权的任务进入人工队列。任务卡显示具体页面、所需动作及恢复方式。按批次筛选执行中、待人工、已暂停、已中断及已完成任务。暂停和中断保留已记录进度，继续从检查点恢复。停止关闭自动执行，用户可手动继续。仅确认未点击发表的临时失败进入后续周期重试，提交结果不明确的只读核验。历史结果可查看及导出。
6. 在侧边栏的任务进度内查看记录摘要，按需查看完整报告或导出 CSV、Excel。每条记录对应一个推广站点及一个外链来源行。后续回访更新原行，保留事件时间线。

## 3. 站点、身份和内容档案

| 对象 | 保存内容 | 应用规则 |
|---|---|---|
| 推广站点 | 官网、品牌名、行业、联系邮箱、语言、Logo、截图 | 每个站点独立管理台账与授权，可通过 DNS TXT 或指定文件验证域名 |
| 品牌内容 | 产品名称、标语、关键描述、产品介绍、核心功能和亮点、关键词、用户确认的事实、译文 | 记录版本，手工修改的内容优先复用 |
| 允许推广的页面 | 首页、产品页、工具页、文章页及主题 | 每次选一个符合栏目要求的目标 |
| 发布身份 | 作者或公司、联系邮箱、站点专用邮箱、平台账号标识、授权状态 | 登录后核对当前身份 |
| 平台内档案 | 平台产品或组织 ID、所属账号、编辑页和公开页 | 先查既有档案，唯一匹配就复用；多个匹配等待确认 |

目录站资料可在推广站点编辑中维护。产品资料、作者或公司、产品图片（支持多张上传或填写多个网址）、分类及资料语言按目标表单要求使用。资料可分步保存，缺少目标入口必填项时转人工。账号和台账按工作空间隔离。插件登录、第三方 Google 登录和 Gmail 读取分别授权。用户在 Google 官方页面输入密码和二次验证信息。

## 4. 导入、校验与去重

| 来源 | 解析规则 |
|---|---|
| Excel | 支持 .xlsx、.xls，可选择工作表，识别表头、普通 URL 和带显示名称的超链接 |
| CSV | 处理有无表头、逗号、分号、制表符、引号内换行和编码预览 |
| TXT | 从逐行网址或带备注文本中提取一个或多个网址 |
| 直接粘贴 | 支持纯文本及从 Excel、网页复制的多列表格 |

表格可映射待分析 URL、已知投稿入口、名称、备注。同一行的展示页和投稿入口关联到同一条候选。保留原始值、文件名、工作表、行号和规范化地址。校验公开 HTTP/HTTPS 地址及跳转目标。访问失败、超时和入口失效的外链暂不导入。错误行可下载并修正，已保存外链清单支持单份或全部导出。

**跨批次去重**：同一工作空间内，执行前以稳定推广站点 ID 和规范化外链 URL 查询共享状态。已处理的终态直接跳过并关联原结果，进行中等待原任务结果，未处理的组合原子认领。每条处理完成后异步写入结果并更新关联批次。仅分析与实际提交分阶段记录。

**三次检查**：导入时合并相同候选并保留所有来源行；分析前查询历史及无效平台清单；发表前由服务端原子占用「推广站点 + 平台」唯一名额。不同栏目、入口和批次共用这项约束。共享托管域名上的独立站点分别识别，已确认的别名和重定向归到同一平台。人工历史支持补录。登录后发现已有申请或公开档案时，关联旧记录。

## 5. 平台分析

1. 检查已有平台记录、失效原因、有效期和历史任务。
2. 读取页面与最终地址，记录正常、跳转、登录墙、受限、超时或失效。
3. 验证用户给定入口；缺少入口时，从来源页、导航和投稿说明寻找。竞品展示页、搜索框、联系表单和投稿表单分别识别。
4. 分类为评论、产品目录、资源推荐、组织档案、文章、纯 URL 提交等。
5. 记录费用、行业、地区、语言、回链、登录方式、建档、资料和验证码要求，每项附来源和证据。登录前不可见的要求记为未知。
6. 读取控件标签、类型、字数、选项和附件要求，生成字段映射与链接写入计划。
7. 保存多标签分类和当前下一步。例如「免费、需 Google 登录、需产品档案；当前动作：登录后检查既有档案」。

仅分析模式只读。规则和控件用途不明确时自动记录并继续队列，客户无需手工录制平台规则。

## 6. 技术架构和成本

- **Chrome Manifest V3 扩展**承担侧边栏、导入、任务页、内容脚本和后台调度。后台随时可能休眠，每步保存检查点。执行代码和依赖随扩展发布。
- **本地分析**优先读取 DOM。已验证的平台规则优先，其次按控件、多语词表和页面上下文判定。可使用 Mozilla Readability 在文档副本上提取文章或投稿指南；实际表单从原页面读取。
- **可选 AI**仅接收相关说明、控件摘要和允许使用的品牌事实。区分分析预算与文案预算。建议陌生入口首次最多调用一次分析，结论经过验证后复用。额度耗尽则处理可判定任务，其余写明原因。
- **可选外部能力**包括设备支持时的 Chrome 本地模型，以及读取独立公开指南的 Jina Reader。客户无需安装 ego(lite) 或其他客户端。
- **后端**负责权限、站点授权、跨设备唯一约束、经验库及报告同步。服务端不可用时暂停最终发表。API 密钥、密码、Cookie、验证码和完整激活链接不进入报告或普通日志。

## 7. 模板、语言与链接

优先选用「平台 + 栏目 + 投稿类型 + 语言」模板，再使用同类模板或推广站通用内容。实际文案和模板版本与任务绑定。用户可维护和删除内容模板并设置默认项，已创建批次保留原模板版本。新建执行批次时可多选内容模板，每条任务在所有适用的选中模板中随机选取一份，并保存版本及文案供续跑复用。用户也可选择 AI 根据目标网页主题与投稿要求独立拟写，或先选模板再交由 AI 结合页面调整。AI 草稿经用户编辑确认后可以另存为内容模板。模型不可用或有效网页内容不足时转人工。后端外链模板知识库按外链域名与入口类型查找经验证的填写规则。域名相同、路径不同的入口在表单结构匹配时复用字段映射，免去重新分析。表单字段、选项或提交方式变化时重新识别。规则保存字段用途，不保存某个推广站点的实际填写内容。

| 场景 | 生成规则 |
|---|---|
| 评论 | 根据当前页面生成一条简短相关评论，遵守客户每条字数及每批数量上限；提交待核实也占本批名额 |
| 文章 | 按栏目和落地页主题准备标题、摘要、正文，优先使用客户成稿 |
| 目录、建档 | 按实际字段选品牌名、官网、简介、分类和素材 |
| 纯 URL | 仅填写目标 URL，零文案调用 |

区分页面语言、接受的投稿语言和字段语言。日语或韩语界面仅作为线索，要求本国语言时保存明确证据。逐字段匹配本地语言版本并按平台计数器校验。缺少资料时依授权生成或暂停；品牌名使用官方译名或原名。

链接优先使用平台专用 Website 字段，其次是编辑器自带的「插入链接」或资源卡片。在明确支持时可用自动转链接、Markdown 或 HTML 源码模式。预览阶段若仅显示文本，撤销原写法，在同一草稿内用另一种受支持的方式插入。一次投稿只选一个链接位置。核验实际目标、锚文本和链接属性。

## 8. 登录、验证与发表

| 情况 | 处理 |
|---|---|
| 已登录或 Google 登录 | 核对当前账号；首次授权、选账号和二次验证交用户。返回后重读页面 |
| 邮箱注册 | 使用指定品牌邮箱。已有账号转登录；自动收信须单独 OAuth 授权，按收件人、发件人、时间、验证域名匹配，唯一匹配才继续 |
| 需建档 | 按域名和账号查找，缺少才创建。若建档即发布，创建动作执行发表前占位并转核验 |
| 人机验证、缺业务字段 | 暂停当前任务，保留页面和检查点，人工完成后重新读取 |
| 付费、回链、特殊声明 | 展示要求并检查批次授权，未获授权则暂停或跳过 |
| 初次点击转登录 | 保留原任务和草稿。若登录后已自动发表，关联已有记录；仅在明确仍为未发表草稿且要求确认时继续原任务 |
| 登录后最终发表失败 | 保存错误并结束，自动重试为零 |
| 点击后断网、重启、无回执 | 只读查后台、原页或公开记录，无法确定则保留待核实 |

最终点击前持久化发表意图，写入唯一尝试记录。即使无法区分「已点击」和「写完记录但尚未点击」，恢复时也优先避免重投。提交后不改文案、换入口或重新登录再投。

## 9. 核验与长期经验库

每次发表后分别验证平台接收、公开可见和链接有效。优先用记录 ID、回执或永久链接定位；评论可按账号、内容、时间、回复层级及分页匹配。链接核验限定到本次内容，防止把页面其他位置的同域名链接算为成功。

| 证据 | 台账结论 |
|---|---|
| 有申请编号，明确等待审核 | 已接收、待审核，只读回访 |
| 提示成功但找不到评论 | 评论未找到，待核实，禁止重投 |
| 作者登录可见 | 记录作者可见，公开视图验证后再更新 |
| 公开内容存在，网址为纯文本或被过滤 | 投稿已发表，外链无效 |
| 公开内容的链接可点击且目标正确 | 有效外链，保存发布地址、目标和时间 |
| 明确拒绝或停止收录 | 未成功，保存平台提示和适用范围 |

活跃外链清单根据最近有效检查结果持续更新。外链入口须经检查确认可用才进入清单，关闭、不可用或检查过期时退出展示。执行端定期回查并回传结果，过时的结果不可覆盖新结果。所有分析、成功、失败、跳过和人工结论均长期积累。记录发生于页面、栏目还是整个平台。首次提示成功但未显示时可暂停新投稿；回访确认持续不公开后，进入工作空间无效平台清单，其他推广站也跳过。明确待审核的继续回访。后续公开时更新结论，保留历史，不释放原推广站已使用的投稿名额。

## 10. 报告与数据

工作台、CSV 和 Excel 的明细统一使用以下前七列，第八、九列分别为「推广站点」和「推广站点网址」。其他字段继续追加在右侧。以下为前七列示例。

| 序号 | 网站域名 | 网站分类 | URL | 结果类别 | 结论 | 原因与下一步 |
|---|---|---|---|---|---|---|
| 1 | tools.example | 目录站 | https://tools.example/add | 提交成功 | 有效外链 | 公开产品页的官网链接已指向预期目标，记录公开页并结束。 |
| 2 | blog.example | 博客 | https://blog.example/post/8 | 未成功 | 待核实 | 页面提示成功，按账号和文案未找到评论。仅回访原页。 |
| 3 | forum.example | 论坛 | https://forum.example/topic/3 | 未成功 | 需人工 | 发表前出现人机验证，用户完成后继续原任务。 |
| 4 | offline.example | 未识别 | https://offline.example/add | 未成功 | 访问不了 | 页面加载超时，未执行提交。下次仅复查可访问性。 |
| 5 | list.example | 目录站 | https://list.example/submit | 提交成功 | 待审核 | 已取得申请编号，等待平台审核后查公开页。 |
| 6 | tools.example | 目录站 | https://tools.example/blog | 未成功 | 已跳过 | 同一推广站已在序号 1 的入口提交，查看原记录。 |

序号按外链清单原始导入顺序从 1 分配。同一来源行在不同推广站点保留各自结论，使用推广站点和原序号共同定位。批次保存启动时的推广站点与外链快照，后续清单变更不改写旧批次。URL 保留原始输入，网站域名取该 URL 的主机名；无有效域名时填「—」。网站分类取平台档案，按下方网站分类字典取值。

结果类别只取「提交成功」或「未成功」。取得可核验的接收记录或已找到本次发表内容，记为提交成功；其余表示本行截至报告时尚未确认提交成功，由结论注明明确失败、待核实、需人工或已跳过。跳过行不计入实际尝试数。已发表但链接只有纯文本时记为「提交成功 / 外链无效」。后续获得新证据时更新原行。原因与下一步写明观察到的事实，以及结束、只读回访或需用户完成的具体动作。

顶部统计原始行数、去重平台数、尝试数、接收数、公开数、有效外链数、失败、人工、待核实和跳过数。每条输入可追溯到平台、实际入口、决策原因、证据、时间、回执、公开地址、实际目标及人工动作。重复项关联原任务。剩余任务都在等待时先出阶段报告。

主要数据对象为工作空间、推广站、资料版本、导入批次、原始行、平台与别名、入口规则、模板版本、平台内档案、任务、唯一尝试、事件、回访和停用记录。对规则、模板和历史结论保留版本，每次执行引用当时版本。

### 网站分类字典

每个平台选一个主要类型，依据首页及主要业务栏目。具体页面另记入口类型，例如论坛、博客都可能有评论入口。AI、教育、电商等行业，以及语言、免费或付费，另作标签。

| 网站分类 | 判断依据 |
|---|---|
| 博客 | 以作者或团队发表文章为主 |
| 论坛 | 以版块、主题帖和回帖为主 |
| 问答社区 | 主要内容由问题和回答组成 |
| 内容社区 | 用户可开设主页并发布文章、作品或动态 |
| 新闻媒体 | 由编辑部组织报道、专栏或客座投稿 |
| 目录站 | 按类别收录网站、工具或资源，含导航站 |
| 产品发布平台 | 围绕新品发布、展示和反馈组织内容 |
| 商家黄页 | 按行业或地区展示企业、门店和联系方式 |
| 应用市场 | 展示可安装或购买的应用、插件及集成 |
| 评测平台 | 以产品评价、评分或对比为主 |
| 开发者平台 | 以代码项目、技术协作或开发资源为主 |
| 知识库／Wiki | 以协作编辑的词条和参考资料为主 |
| 社交书签站 | 用户收藏、整理和分享外部链接 |
| 行业协会／组织站 | 以会员名录、组织活动和行业资源为主 |
| 企业官网 | 主要展示一家企业的业务，可能设合作伙伴或案例入口 |
| 其他 | 已确认用途，现有类别无法覆盖；记录实际用途 |
| 未识别 | 当前证据不足；后续分析可更新 |

### 结论字典

每行选择一个能解释当前结果的结论。「结果类别」按已有接收证据判定；只读回访可以更新结论。括号中的具体情形写入「原因与下一步」，不额外增加导出列。

| 结论 | 判定依据及处理 |
|---|---|
| 有效外链 | 已在公开投稿中核验可点击链接及预期目标，计入有效数 |
| 外链无效 | 内容已公开，但链接被过滤、仅剩纯文本或目标错误；记录实际情况 |
| 待审核 | 有可核验的接收记录且平台明确标记审核中；记录编号并回访 |
| 待核实 | 提示成功却找不到评论、发表后超时或公开状态未知；只读检查 |
| 仅作者可见 | 作者账号能看到，已核验公开视图没有对应内容；保留核验时间 |
| 已下线 | 原有公开记录后续被删除或撤下；保留首次成功和本次回访证据 |
| 访问不了 | 域名无法解析、加载超时或服务端异常；记录故障范围，安排访问复查 |
| 页面失效 | 当前 URL 已删除或返回 404、410；仅对该页面生效 |
| 访问受限 | 当前环境无访问权限或受到地区限制；记录限制说明 |
| 未找到入口 | 查过来源页、导航及说明，仍无法定位适用入口 |
| 已关闭投稿 | 页面明确说明关闭投稿或评论，记录页面或栏目范围 |
| 条件不符 | 站点行业、地区、语言等不满足明确要求；记录具体条款 |
| 提交被拒 | 最终发表后明确拒绝；保存错误原文并停止 |
| 需人工 | 有具体动作可解除阻塞，如人机验证、选择账号、邮箱验证、补档案、确认付费或回链 |
| 已跳过 | 重复 URL、历史已尝试、命中无效平台、超批次限额或用户跳过；关联来源记录 |
| 输入无效 | 地址无法解析或协议不受支持；提示修正原始输入 |
| 仅分析 | 本批只分析，保存可用入口、资料要求及建议动作 |

例如同一目录站明确拒绝了投稿，结论取「提交被拒」，原因写明日语必填；若在发表前已发现该条件且用户可以提供日语简介，则取「需人工」。平台有申请编号并待审可归「提交成功 / 待审核」；仅出现成功弹窗而找不到评论归「未成功 / 待核实」。

## 11. 实施顺序

1. 交付登录、站点档案、四类输入、行级台账和历史去重。
2. 实现只读入口分析、页面快照、多语言词表、分类和证据存储。
3. 打通免登录投稿、原子占位、链接预览、提交核验和导出。
4. 接入登录续跑、注册、邮箱验证、建档和人工队列。
5. 加入经验复用、无效渠道、只读回访、可选 AI 与成本统计。
6. 在获准测试的平台进行混合批次验收，记录零 AI 完成率、人工介入率和每条有效外链的 AI 成本。

## 12. 验收用例

| 输入或故障 | 预期结果 |
|---|---|
| 等价清单分别由 Excel、CSV、TXT 和粘贴导入 | 生成等价候选，每个原始行可查询 |
| 同平台五个 URL，两个批次同时执行 | 最多一次投稿尝试，其余关联原记录 |
| 日语表单要求日语简介且 AI 关闭 | 有译文自动填，缺译文仅挂起该任务 |
| 富文本预览只有纯文本，工具栏支持链接 | 在草稿内改用链接按钮并核验，只发表一次 |
| 登录后自动发表或明确拒绝 | 前者关联原记录，后者记录失败并停止 |
| 点击后断网、无回执、重启 | 恢复后只读查询，无第二次提交 |
| 提示成功但未出现评论 | 报告零条有效外链；回访确认持续不显示后停用 |
| 新推广站首次遇到已验证入口 | 复用平台规则和模板，填入新站自己的资料 |
| 一个渠道有人机验证，另一个免登录 | 前者进入人工队列，后者继续完成 |
| 批次含成功、失败、待审核和重复行 | 工作台、CSV 和 Excel 前七列名称及顺序一致，逐行保留序号、原因和下一步 |

回访间隔、判定持续不公开的观察期、AI 供应商与预算、商业套餐由产品配置确定。首版完成条件是标准表单可零 AI 执行、用户无需配置控件、提交故障不重投、每条输入均有可解释结论。
